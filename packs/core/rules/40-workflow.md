---
title: How to work in this repo
order: 40
---
- Read before writing. Locate the existing pattern and follow it rather than
  introducing a second way of doing the same thing.
- Prefer editing an existing file over creating a new one. New top-level
  directories need a reason.
- Make the smallest change that fully solves the problem. Do not refactor
  adjacent code opportunistically in the same change.
- Finish the whole task. If part of it is blocked, complete the rest and say
  explicitly what was left undone and why.
- Never claim something works because it compiles. Run it.
